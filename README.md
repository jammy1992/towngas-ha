# 港华燃气 · Home Assistant 集成（通用版）

把港华燃气的户号接进 Home Assistant：燃气表累计读数、账户余额、昨日用气量、昨日气费。
走的是港华微门户（`weixin.towngasvcc.com`）的微信 OAuth 授权 + 官方 H5 接口，**不需要抓包、不需要输入密码**。

> **本仓库不是港华燃气的官方项目**，与港华燃气集团及其任何分公司无关。
> 详见文末 [免责声明](#免责声明)。

## 它做了什么

- **微信扫码授权**：添加集成时直接显示二维码，手机微信扫一扫，把跳转链接粘回来即可
- **户号自动识别**：授权完直接读账号名下的户号，不用手抄 subsId
- **Token 自动保活**：独立定时器每 30 分钟刷新一次 `refresh_token`，与数据刷新解耦
- **失效自动重授权**：`refresh_token` 真的失效时触发 HA 原生 re-auth 流程，UI 上会弹出「重新认证」
- **通用分公司支持**：内置全国 176 家港华/港能/佛燃系分公司，下拉选择即可，**不再把某一家的 clientId 写死在代码里**
- **四个实体**：累计读数（可进能源面板）、账户余额、昨日用气量、昨日气费
- **可下载诊断信息**：条目菜单里一键导出脱敏后的配置与接口返回，排错不用猜

数据获取节奏：每 6 小时一次（可改），23:30–00:30 港华每日维护窗口自动跳过。

## 修改来源与差异

本仓库是 [`palafin02back/hztowngas`](https://github.com/palafin02back/hztowngas)（MIT License）的衍生版本。
上游基于 `v1.0.6`，原本只适用于**杭州余杭港华**——它的 `const.py` 里写死了

```python
DEFAULT_CLIENT_ID = "pe92a8wechatYH0105"   # YH0105 = 杭州余杭
```

本项目在它的基础上做了以下修改：

| # | 修改 | 说明 |
|---|---|---|
| 1 | **clientId 不再硬编码** | 改为「选择分公司 → 自动拼出 clientId」，并提供手填 clientId 的兜底输入框 |
| 2 | **内置分公司清单** | 新增 `branches.json`（176 家，来源于港华官网 `orglist` 接口），添加集成时下拉选择 |
| 3 | **新增实体：账户余额** | 上游只把 `savingSum` 塞在属性里，这里做成独立的 `monetary` 实体 |
| 4 | **新增实体：昨日用气量、昨日气费** | 需要跨两次抄表做减法，新增 `daily.py`：把「上期抄表日 + 读数」持久化到 `.storage/hztowngas_daily.<entry_id>`，跨日时求差；同日修订、读数回退、重复拉取都有对应分支 |
| 5 | **配置流程重排** | 分公司 → 扫码 → 填户号，三步；authCode 支持直接粘贴整条 URL（自动截取） |
| 6 | **重新授权可换分公司** | re-auth 时若已知 clientId 直接出二维码，未知则先让你选分公司 |
| 7 | **条目迁移 v1 → v2** | 旧条目无需重新扫码（`refresh_token` 与 clientId 无关），升级后照常工作 |
| 8 | **默认气价可配置** | 接口没返回单价时用选项里的默认值，不再写死 3.45 |
| 9 | **clientId 预校验** | 选完分公司会先请求一次授权地址，拉不起微信就当场报错，不会让你白扫一个无效二维码 |
| 10 | **户号自动识别** | 扫码成功后直接读账号名下的户号（`getLoginUserInfo` / `getSubsList` / `getUserSubs` 依次尝试），单户自动填入、多户下拉选择，**不用再手抄 32 位 subsId** |
| 11 | **10001 分诊** | 用「账号接口能否读到户号」区分「分公司选错 / 令牌失效」与「户号不属于该账号」，报错给出可执行结论，并在户号不匹配时自动触发重新授权 |

上游的原始能力（OAuth 兑换、签名、`preCheck` 取数、维护窗口跳过、401 重试）全部保留，未做改动。

## 安装

### 方式一：HACS 自定义仓库（推荐）

1. HACS → 右上角「⋮」→ **自定义存储库**
2. 填入本仓库地址 `https://github.com/jammy1992/towngas-ha`，类别选 **Integration**
3. 在 HACS 里搜索「港华燃气」→ 安装
4. **重启 Home Assistant**

### 方式二：手动

把 `custom_components/hztowngas` 整个目录复制到 HA 配置目录下：

```
config/custom_components/hztowngas/manifest.json   ← 最终路径应为此
```

然后重启 HA。

> 依赖 `qrcode[pil]`（画二维码用），HA 会在启动时自动安装，无需手动 pip。

## 首次配置

**设置 → 设备与服务 → 添加集成 → 搜「港华燃气」**

**第 1 步：选择分公司**
下拉里按公司名排序，找到你的供气方（例如「杭州余杭港华燃气有限公司」）。
如果这家分公司不按常规规律生成 clientId，可以在第二个框手填 clientId（见下一节）。

**第 2 步：微信扫码（户号自动识别）**

- 用**手机微信**扫描页面上的二维码。**不要用 PC 浏览器打开**，会被拦。
- 扫完出现白屏是正常的：把地址栏那条链接**整条**复制下来，粘到第一个输入框（`authCode=` 后面的值会自动截取）。
- **不用再手抄 subsId**：授权成功后集成会直接读取这个微信账号名下的户号——只有一户时自动填入，多户时给你下拉选。
- 其余保持默认即可，提交。

成功后会生成一台设备「港华燃气表 <户号>」，下面挂 4 个实体。

## 找不到 subsId / subsCode？

**2.1.1 起通常不需要看这一节**：户号由集成自动读取。只有两种情况会退回手填——
① 该分公司的账号接口不返回户号列表；② 你手动选了「手填户号」页面。

如果确实要手填，这两个值只在登录后的「户号列表」接口里出现，**必须让网页自己发起请求才能看到**（直接在地址栏敲 `/user/querySubsList` 不行，不少分公司的站点是 Vue 单页应用，路由会被前端接管并跳回首页）。

任选一种：

- **看请求**：电脑 Chrome 登录官网 → `F12` → 网络 → `Fetch/XHR` → 点进「个人中心 / 我的 / 户号管理」→ 找返回里有 `subsId`、`subsCode` 的那条 → 复制两个值
- **导出 HAR**：`F12` → 网络 → 右键任意请求 → 「全部另存为 HAR」→ 用文本编辑器打开，全局搜 `subsId`，前后就是
- **看地址栏**：部分站点进「户号详情」后 URL 里带 32 位串，那就是 `subsId`

字段长这样：

```json
{"resultCode":"0","datas":[{"subsId":"0123456789abcdef0123456789abcdef",
  "subsCode":"1234567890","subsName":"张三","subsAddr":"某某花园 3 栋 501"}]}
```

- `subsId`：32 位十六进制串
- `subsCode`：纯数字户号（8–12 位）

> 手填的户号会先试抓一次数据，抓不到会当场报错，不会写进一份注定不可用的配置。
> 名下有多块表：重新添加条目并在「选择户号」里选另一户即可。

⚠️ HAR / 请求 URL 里带着你的登录 token 和真实姓名地址，**用完记得删掉**。

## 分公司与 clientId 的对应规则

微信 OAuth 的 clientId 规律是：

```
clientId = "pe92a8wechat" + 分公司 orgCode（去掉下划线）
```

| 分公司 | orgCode | clientId | 结果 |
|---|---|---|---|
| 杭州余杭港华 | `YH0105` | `pe92a8wechatYH0105` | ✅ 302 → 微信 |
| 常州金坛港华 | `JJ0105` | `pe92a8wechatJJ0105` | ✅ 302 → 微信 |
| 济南港华 | `LX_JN0105` | `pe92a8wechatLXJN0105` | ❌ 返回 `{"resultCode":"10001"}` |

上表只是抽样示意，用来印证规律本身；任何一家都能用同样的方法自己验证（把 clientId 拼好后请求授权地址，看是否 302 到 `open.weixin.qq.com`）。

所以：

- **大部分分公司**选一下就行，集成会自动拼 clientId 并先验证一次
- **少数分公司**（走总部站、只支持短信登录的那种）拉不起微信，会提示「clientId 未生效」，这时需要自己弄到可用的 clientId 填进第二个框
- 注意别用「只去掉前缀但不带地区前缀」的写法：`DY0105` 是四川大邑港华，扫了会授权到别人家的公众号上

## 实体说明

| 实体 | 单位 | 说明 |
|---|---|---|
| `sensor.<户号>_燃气表读数` | m³ | 累计读数，`gas` + `total_increasing`，可直接加入能源面板 |
| `sensor.<户号>_账户余额` | CNY | 接口的 `savingSum`；属性里有取值字段名、扣费类型、抄表日期 |
| `sensor.<户号>_昨日用气量` | m³ | 相邻两次抄表读数之差；属性带起止日期、覆盖天数、上下期读数 |
| `sensor.<户号>_昨日气费` | CNY | 昨日用量 × 单价；单价优先取接口 `gasFee.gasFeeList[0].price`，否则用选项里的默认气价 |
| `button.<户号>_立即刷新` | — | 立刻拉一次数据（别频繁按，会被限流） |

**关于「昨日用气量 / 昨日气费」**：

- 首次启动只建立基线，实体显示「未知」，要等**下一次抄表日**才有第一个值；
- 如果 HA 停了几天，那次算出来的用量会覆盖多天（属性里的「覆盖天数」会显示 2、3），不是算错；
- 读数倒退（换表、接口抽风）会重置基线而不是产出负值。

## 从旧版本升级

从 **上游 v1.0.6** 或 **本项目的 v1.0.7 / v1.1.0** 升级到 v2.0.0：

1. 覆盖 `custom_components/hztowngas/`，重启 HA
2. **不需要重新扫码**：配置条目会自动从 v1 迁移到 v2，`refresh_token` 与 clientId 无关，旧令牌继续有效
3. 三个新实体（余额 / 昨日用气量 / 昨日气费）会自动出现
4. 迁移后的条目里 clientId 是空的，只有将来需要重新授权时才要求你选一次分公司

反过来说：如果你之前用的是**硬编码某家分公司**的旧包，且升级后想改分公司，直接在「配置 → 重新认证」里选新分公司并重新扫码即可。

从 **2.0.0 / 2.1.0** 升级到 **2.1.1**：覆盖目录并重启即可，配置条目不用动。

如果升级后所有实体都不可用、日志里报 `10001`，按这个顺序处理：

1. **重新授权**（设置 → 设备与服务 → 港华燃气 → 三个点 → 重新授权）。2.1.1 的第一步一定会显示分公司下拉，默认选中你当前记录的那家——核对它和你的供气方全称是否一致（同一城市有多家分公司时尤其容易混），提交后重新扫码。
2. 仍然 `10001`，就**删除条目重新添加**。注意：删除会一并清掉「昨日用气量 / 昨日气费」的本地读数快照，重建后这两个实体要从第二天起才会出数。

> 覆盖安装只替换代码，**不会改写你原有的配置条目**。条目里存的分公司 / clientId 若与令牌不匹配，这个错误会原样带到新版本里——这也是「装了新版依旧不可用」最常见的原因。

## 已知限制

- **数据延迟**：纯云端集成，秒级到几十秒延迟；表本身一天一报，别指望实时
- **气价档位**：「昨日气费」按当前单价计算，跨阶梯后实际单价更高，日费用会略微偏低
- **接口随时可能变**：这是非官方接口，港华改了 `app_id` / 签名盐 / 路径就得等更新
- **别在别处登出同一个微信**：会让 `refresh_token` 立即失效，这是「用几天就掉线」最常见的原因
- **维护窗口**：每日 23:30–00:30 港华维护，这段时间取不到数属正常
- **只有查询能力**：不缴费、不充值、不改任何设备状态

## 排错

`configuration.yaml` 里打开调试日志：

```yaml
logger:
  logs:
    custom_components.hztowngas: debug
```

| 现象 | 多半是 |
|---|---|
| 提示「clientId 未生效」 | 这家分公司不走这套规律，手填 clientId |
| 提示「兑换 Token 失败」 | authCode 已用过 / 过期，重新扫码（authCode 一次性） |
| `API 错误 10001: 系统正在升级中......` | **分公司选错了**（最常见）或户号不属于该微信账号，见下一节 |
| 提示「户号不属于当前登录账号」 | 报错里会列出该账号名下的户号，用「重新授权」重选一次 |
| 实体建好了但没数据 | `subsId` 和 `subsCode` 填反了，或这个微信没绑定该户号 |
| 数值一天不动 | 正常，NB-IoT 表一天上报一次 |
| 过几天变成「不可用」 | 令牌失效，UI 会提示重新认证；检查有没有在别处退登 |

### `API 错误 10001: 系统正在升级中......` 怎么处理

`10001` 是港华网关的**万能失败码**，那句「系统正在升级中」是固定文案，几乎和停机维护无关。真实原因只有两种：

1. **分公司选错了** —— 微信 OAuth 是按分公司发 `clientId` 的，任何一家分公司的 `clientId` 都能拉起微信并**授权成功**，但拿到的令牌只属于那家分公司。用它去查别家的户号，网关就回 10001。例如供气方是「杭州余杭港华」，别选成「大邑港华」（`DY0105`）——两者 clientId 分别是 `pe92a8wechatYH0105` 与 `pe92a8wechatDY0105`，差一个地区前缀。
2. **户号不属于这个微信账号** —— 例如 subsId 抄错一位、或用了别人的户号。

2.1.1 起集成会先自行区分：账号接口能读到户号 → 报「户号不属于当前登录账号」并列出可用户号；账号接口也 10001 → 判定为登录态/分公司不匹配，直接弹出「重新授权」。

排查顺序：

1. **配置 → 齿轮**，页面顶部会显示当前分公司与 clientId。用「分公司名 + clientId 是否等于 `pe92a8wechat` + 该分公司 orgCode（去下划线）」核对，对不上就是选错了。
2. 不对就删除条目重新添加，在下拉里搜你所在城市的关键词，选全称与你的供气方完全一致的那一条。
3. 对的话点「重新授权」重扫一次，集成会自动把户号换成账号里的正确户号。
4. 还是不行：三个点菜单里「**下载诊断信息**」，里面有脱敏后的配置和最后一次接口返回，贴到 issue 里即可（令牌已打码）。
